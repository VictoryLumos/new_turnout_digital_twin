## 修复 1：空数据集守卫（原三处未拒绝）

- 推送服务：空 JSON 原触发 IndexError 栈回溯 → 现明确'数据集为空，拒绝推送'退出 1；
- db/02 入库：空数据原在 min()/批量插入处崩溃 → 现'数据集为空，拒绝入库'；
- /api/play：空数据集原返回'开始回放 0 行'（误导成功）→ 现 HTTP 400。

## 修复 2：回放停止事件改私有（并发双写隐患）

- 原实现 _play['stop'] 为全局共享 Event：旧回放线程若因数据库卡顿未能在 join(3s)
  超时内退出，下一次 api_play 的 clear() 会把旧线程'复活'，两线程同时写实时表；
- 现改为每轮回放持有私有停止事件（playback(condition, rows, stop_evt)），
  停止只 set 当前事件、永不 clear 旧事件——旧线程必定退出；
- 实测：/api/stop 后 realtime_value.max(updated_at) 两次采样不变；
  快速切换回放再停止同样无残留写入。
