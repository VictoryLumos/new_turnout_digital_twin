## 1. 兼容性总则（v2 的核心设计）

1. **基础 3 字段冻结**：`time`、`switchRailDisp1`、`pointRailDisp1` 的名称、单位、
   步长与 v1.0 完全一致，任何消费方（C 页面、脚本）不因 v2 改动任何一行代码；
2. **新增 17 字段全部为可选**：数据文件里可以出现也可以不出现；
3. **消费方必须忽略未知字段**（前向兼容）：C 的页面解析 JSON 时只取自己需要的
   字段，多余字段直接跳过——这是三方都要遵守的解析纪律；
4. **数据源三选一**（与 v1.0 一致）：本地 JSON 文件直读（默认）/ WebSocket 实时
   推送 / HTTP 服务接口（v2 新增，见第 5 节），任一失败退回本地 JSON，不阻塞交付。

## 2. 字段全表（time + 20 测点字段）

### 2.1 必选字段（v1.0 冻结项）

| 字段 | 测点编码 | 单位 | 含义 | 告警阈值 |
|---|---|---|---|---|
| time | — | s | 仿真时刻，步长 0.1s | — |
| switchRailDisp1 | T01-SR-01-DISP | mm | 尖轨牵引点1位移 | **>150**（前端变红） |
| pointRailDisp1 | T01-PR-01-DISP | mm | 心轨牵引点1位移 | **>100**（前端变红） |

### 2.2 可选字段（v2 增补，按《完整版》编码映射表）

| 字段 | 测点编码 | 单位 | 含义 |
|---|---|---|---|
| switchRailDisp2 / 3 | T01-SR-02/03-DISP | mm | 尖轨牵引点2/3位移 |
| switchRailForce1 / 2 / 3 | T01-SR-01/02/03-FORCE | N | 尖轨牵引点1/2/3牵引力 |
| pointRailDisp2 | T01-PR-02-DISP | mm | 心轨牵引点2位移 |
| pointRailForce1 / 2 | T01-PR-01/02-FORCE | N | 心轨牵引点1/2牵引力 |
| switchMachineCurrent | T01-SM-01-CURR | A | 转辙机电机电流 |
| switchMachinePower | T01-SM-01-POWER | W | 转辙机功率（P=U·I，U=220V） |
| lockStatus | T01-SM-01-LOCK | 0/1 | 锁闭表示（1=已锁闭） |
| closeStatus | T01-SR-01-CLOSE | 0/1 | 密贴表示（1=已密贴） |
| frogVibration | T01-FR-01-VIB | m/s² | 辙叉振动加速度 |
| frogWear | T01-FR-01-WEAR | mm | 辙叉磨耗 |
| wheelRailForceLateral | T01-FR-01-WRF-L | kN | 轮轨横向力（列车通过时段） |
| wheelRailForceVertical | T01-FR-01-WRF-V | kN | 轮轨垂向力（列车通过时段） |
| guardRailDisp | T01-GR-01-DISP | mm | 护轨位移 |
| railTemperature | T01-BR-01-TEMP | ℃ | 基本轨轨温 |

> 其余测点的告警阈值待 A 确认编码映射后入库冻结（《数据库表结构设计》协作机制）。
> 0/1 状态量不设阈值，走健康度规则判据（稳态门，详见服务 API 健康度评分说明）。

## 3. 数据文件与消息

| 载体 | 内容 | 用途 |
|---|---|---|
| `data/data.json` | 80 行 × 基础 3 字段（v1.0 原样） | 基础版 C 页面联调默认通道 |
| `data/扩展数据集v2/工况_*.json` | 100 行 × time+20 字段，四工况各一份 | 完整版服务层回放/历史/识别的数据源 |
| WebSocket 消息（ws://B的IP:8765） | **行对象原样推送**（data.json 里有什么字段就推什么字段）；`WebSocket推送服务.py --dataset 工况` 可直接推送四工况全字段数据（21字段） | 换全字段数据文件后 WS 通道自动升级，无需改推送服务 |

四工况数据集的时间轴与物理设计见 `生成扩展数据集.py` 头部注释（正常转换 / 卡阻 /
密贴不良 / 锁闭失败，各 10s、0.1s 步长，含列车通过辙叉的 8.2~8.8s 脉冲段）。

## 4. 告警与健康度判据（数据侧）

- **阈值告警**（存库 `measurement_point.alarm_threshold`）：`value > 阈值` 即告警，
  目前仅两个位移测点定阈（150 / 100 mm），与前端"超限变红"、监视器标红三方同源；
- **健康度评分**（服务 API 规则模型）：稳态门 + 扣分制，优/良/预警/故障四档，
  扣分项自动关联测点并触发工单（同测点同问题去重）；
- **工况自动识别**（服务 API v2.1）：8 维统计特征 + 同相位前缀最近邻，
  输出识别工况与置信度，属可解释统计识别（非深度学习）。

## 5. HTTP 服务接口（v2 新增通道）

基址 `http://<B的IP>:8000`，**CORS 已放开**——C 的页面（file:// 打开或其他端口）
可直接 fetch，不受浏览器跨源限制。全部接口见服务首页清单，摘要：

| 接口 | 方法 | 用途 |
|---|---|---|
| /api/realtime · /api/alarms · /api/health | GET | 实时值 / 当前告警 / 健康度 |
| /api/history/{测点编码}?limit=n | GET | 历史时序（趋势页数据源） |
| /api/identify · /api/diagnosis | GET | 工况自动识别 / 诊断+维修建议 |
| /api/workorders · /api/repair/{工单号} | GET/POST | 工单看板 / 维修闭环复测 |
| /api/play/{工况} · /api/stop | POST | 行为模型回放注入 / 停止 |
| /api/points · /api/conditions · /api/stats | GET | 测点清单 / 数据集清单 / 系统状态 |
