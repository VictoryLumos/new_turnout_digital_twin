# 三分钟演示剧本（答辩/组长验收用）v1.0

> 对应《B线工作计划》第六节 8 项演示素材的现场串联版。逐字稿按 ~250 字/分钟 口语速度撰写。
> 总口径（开场与收尾都必须说）：**"仿真数据驱动的道岔数字孪生验证原型"**——不说"实时数据""完整数字孪生"。

## 演示前准备（提前 10 分钟，顺序执行）

| # | 操作 | 就绪标准 |
|---|---|---|
| 1 | 确认 PostgreSQL 服务在跑 | `python data/联调自检脚本.py` 全部 [OK]（15项） |
| 2 | 双击 `data/服务API演示.bat` | 浏览器打开 http://localhost:8000/ ，健康度 100/优 |
| 3 | 双击 `data/WebSocket演示.bat`（若演示 WS 段） | 测试页数值每 0.1s 跳动 |
| 4 | 打开 pgAdmin 备用（第 8 幕用） | 能看到 turnout_twin 五张表 |
| 5 | 浏览器标签预开：状态板 / /trend / pgAdmin | 切换零等待 |

## 第 1 幕（0:00–0:20）3D 模型加载 —— C 的页面

**操作**：打开 C 的网页，模型加载完成。
**逐字稿**："这是我们三人协作的道岔数字孪生系统：C 负责网页和 18 号道岔三维模型，A 负责模型构建与仿真数据，我负责中间整条数据管道——数据从哪来、怎么流、怎么存、怎么变成告警和维修决策，接下来三分钟完整走一遍。"
**兜底**：C 页面未就绪 → 用 `WebSocket测试页面.html` 代替并说明"以 C 联调页面为准，这里用数据侧自检页展示同一份数据"。

## 第 2 幕（0:20–0:40）尖轨动作与超限变红 —— C 的页面

**操作**：播放数据，尖轨/心轨横向移动。
**逐字稿**："尖轨和心轨按数据位移，毫米乘 0.001 换算成模型坐标。尖轨超过 150 毫米——看，构件变红；心轨对照组全程不超 100 毫米就不红。阈值不是写死的，存在数据库测点表里，前端、监视器、服务端三方同源。"

## 第 3 幕（0:40–1:05）实时数据通道 —— WebSocket 监控台

**操作**：切到 WebSocket 测试页（已开）。
**逐字稿**："数据通道有三条：本地 JSON 文件、WebSocket 实时推送、数据库接口，任一条断了自动退回本地文件，不阻塞交付。现在这个监控台连的就是 WebSocket 通道，每 0.1 秒推一条，按绝对时刻对齐，不会越推越慢。"

## 第 4 幕（1:05–1:45）注入卡阻 → 健康度跳水 → 工单自动生成 —— B 主场

**操作**：状态板点"卡阻"。
**逐字稿**："重点来了。我点击注入'卡阻'工况——转辙机先正常动作，3 秒半卡住，电流开始爬升。看健康度：规则模型带稳态门，转换过程中不误报，电机电流超 8 安立刻扣分，评分从 100 掉到 55，等级'故障'。同时告警自动生成维修工单——同一个测点同一个问题只开一张单，防重复。"

## 第 5 幕（1:45–2:05）维修闭环 → 自动复测恢复 —— B 主场

**操作**：工单看板点"维修闭环"。
**逐字稿**："工单闭环不是改个状态就完了——系统自动重演一遍正常转换做复测，数据重新入库，健康度自己回到 100。这就是'维修—复测—恢复'的完整闭环。"

## 第 6 幕（2:05–2:30）工况自动识别（v2.1 新增）—— B 主场·难度展示

**操作**：点"锁闭失败"，等 3 秒，指识别卡片；再开 /api/identify 看特征依据。
**逐字稿**："更进一步——不告诉系统我注入了什么。系统把回放窗口压缩成 8 个统计特征：终点位移、电流峰值、锁闭末态、密贴抖动……和四个工况库做同相位最近邻匹配，自动报出'锁闭失败'，置信度 99%。这是可解释的统计识别，不是黑盒——每个判断都能说出依据（指特征依据一行）。"

## 第 7 幕（2:30–2:50）历史趋势回放 + 诊断建议 —— B 主场

**操作**：开 /trend，选尖轨位移，点"▶ 回放"；再开 /api/diagnosis。
**逐字稿**："历史侧：四工况 8000 条数据都在 PostgreSQL 里，趋势页可以按时间轴回放，红色虚线是告警阈值，卡阻段曲线一目了然。诊断接口把扣分项翻译成维修建议——过流查摩擦联结器，锁闭失败查锁闭检查器，直接对应现场检修规程。"

## 第 8 幕（2:50–3:00）数据库与收尾

**操作**：切 pgAdmin 快速展示五张表行数。
**逐字稿**（收尾口径）："底层是 PostgreSQL 五张表：构件、测点、时序、工单、实时值，时序主键是测点加时间戳，重复导入幂等。最后强调口径：这是一个**仿真数据驱动的验证原型**——数据链路、健康度、工单闭环、工况识别全部真实可跑，接入真实传感器数据时链路不变。谢谢。"

## 常见翻车与急救

| 症状 | 急救 |
|---|---|
| 状态板打不开 | 数据服务黑窗口被关了 → 重双击 `服务API演示.bat` |
| 健康度不变化 | 回放已结束（每工况只放一遍）→ 重新点工况名 |
| 识别显示"--" | 窗口未满 3 秒 → 等一下再指屏；或重开 /api/identify |
| 数据库连不上 | 管理员 `net start postgresql-x64-17` → 重启服务API |
| 全套演示环境崩 | 退路：`WebSocket演示.bat` + 本 README 的 data.json 契约链路，2 分钟能讲完基础版 |

## 答辩一句话兜底（被问到数据真实性时）

"数据是物理量纲合理的仿真数据——四工况由脚本生成、固定随机种子可复现；A 的 UM 仿真数据到位后走同一个转换脚本入库，整条链路不用改。这也是我们叫'验证原型'的原因。"
