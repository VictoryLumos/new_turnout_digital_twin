## 1. B 线在项目中的位置

项目三人分工：A 负责 glTF/GLB 模型，**B 负责数据管道与数据库**，C 负责网页端呈现。B 线一句话概括：**把"数据"从产生到消费的整条链路打通并保证可信**——上游接 A 的仿真数据，下游同时供给 C 的页面联调（基础版）和 PostgreSQL 数据库（完整版线），中间用接口契约保证三方不扯皮。

```
A：UM/MATLAB 仿真 CSV
        │  仿真数据转换脚本.py（CSV → 契约 JSON，自动校验）
        ▼
data/data.json（接口契约文件，文件名定死）
        │                          │
        │ 文件直读（契约默认）       │ 02_数据导入脚本.py
        ▼                          ▼
C：网页读 JSON 循环播放     PostgreSQL turnout_twin 库（五张表）
        ▲                          ▲
        │ WebSocket推送服务.py      │ 实时数据入库.py（0.1s 刷 realtime_value）
        └──── 可选实时推送 ─────────┘
```

基础版联调以 **data.json 文件直读**为默认通道；WebSocket 与数据库是已跑通的两条增强线，任一失败均可退回，不阻塞交付。

## 3. 内容之一：数据契约（data.json）

这是三方协作的基石，出自《数据格式约定_v1.0.md》，**字段与文件名由契约定死，不得改名**：

| 项 | 约定 |
|---|---|
| 文件 | `data/data.json`，JSON 数组 |
| 字段 | `time`（秒）、`switchRailDisp1`（尖轨位移 mm）、`pointRailDisp1`（心轨位移 mm） |
| 步长/条数 | 0.1 秒 × 80 条，覆盖 0.0~7.9 秒，前端循环播放 |
| 坐标换算 | 毫米 × 0.001 = 米（C 端移模型时换算） |
| 告警阈值 | 尖轨 > 150 mm 变红；心轨 > 100 mm 变红（**前端判定**，数据不含告警标记） |

**当前假数据的曲线设计是故意的**：尖轨 0→160mm、6 秒平滑完成转换，5.1 秒起超 150mm（后 29 条超限），专门用于演示"超限变红"；心轨延迟 0.5 秒启动、0→95mm 全程不超限，作为不告警的对照组。演示时"一条红一条不红"的效果即来源于此。

**字段与测点编码映射**（也是库内测点表的主键依据）：

| 数据字段 | 测点编码 | 单位 | 阈值 |
|---|---|---|---|
| switchRailDisp1 | T01-SR-01-DISP | mm | 150 |
| pointRailDisp1 | T01-PR-01-DISP | mm | 100 |

将来 A 的 UM 数据只要按同样字段/步长导出，直接替换 data.json 即可，**C 无需改一行代码**——这是契约设计的核心收益。

## 4. 内容之二：数据推送（WebSocket 可选线）

- 服务读同目录 data.json，按 0.1s 绝对时刻对齐逐条推送（对齐设计抵消了 send 耗时，越推越慢的常见问题已规避），推完自动循环；每个客户端独立从 t=0 开始收。
- 启动时先自检数据文件（条数/步长/时间范围），坏了直接报错不静默。

```bash
python data/WebSocket推送服务.py              # 默认端口 8765
python data/WebSocket推送服务.py --port 9000  # 换端口
```

- C 在同一台电脑连 `ws://localhost:8765`；在局域网其他电脑连 `ws://<B的IPv4>:8765`（B 运行 `ipconfig` 查地址）。
- 演示给组长/队友看：双击 **WebSocket演示.bat**，自动起服务并打开测试页面，浏览器里数值每 0.1 秒跳动、尖轨超限时整卡变红。
- 联调兜底：WebSocket 失败则 C 退回直读 data.json，**不阻塞交付**（契约约定）。

## 5. 内容之三：数据库（PostgreSQL + TimescaleDB）

### 5.1 选型结论

**用 PostgreSQL + TimescaleDB 扩展，单实例同时充当关系库与时序库**，一份安装覆盖《完整版》对两种数据库的要求；TimescaleDB 没装也没关系，建表脚本会自动检测并按普通 PostgreSQL 运行（当前 B 机即此模式，基础数据完全不受影响）。

### 5.2 部署现状（B 机，已跑通）

| 项 | 值 |
|---|---|
| 版本 | PostgreSQL 17.9，装于 `D:\PostgreSQL` |
| 服务 | Windows 服务 postgresql-x64-17，开机自启（没起来：管理员运行 `net start postgresql-x64-17`） |
| 库 / 账号 / 端口 | turnout_twin / postgres / 5432 |
| 当前数据量 | 构件 9、测点 20、时序 8000（四工况 4×2000 + 基础假数据 160）、工单 32+（含告警自动生成）、实时值 20 |

### 5.3 五张表及其关系

```
component（构件表） 1 ── N measurement_point（测点表） 1 ── N timeseries_data（时序表）
                            │ 1                              │
                            └── N work_order（工单表，预留）   └── realtime_value（实时值表）
```

| 表 | 行数 | 作用与要点 |
|---|---|---|
| component 构件表 | 9 | 尖轨/心轨/基本轨/转辙机/辙叉/护轨等，含 glTF 模型节点名（待 A 导出后确认）、资产 ID |
| measurement_point 测点表 | 20 | 一行一个测点；**field_name 与 data.json 字段一一对应**；alarm_threshold 存告警阈值（空 = 待定） |
| timeseries_data 时序表 | 160 | "时间戳 + 测点 + 数值"长表，data.json / UM / 将来真实传感器统一进这张表，source 字段区分来源（fake/um/sensor）；主键 (point_code, ts)，重复导入自动跳过；装了 TimescaleDB 时自动转为 hypertable |
| work_order 工单表 | 20 | 预留，按映射表预置编号，完整版做"告警与工单联动"时启用 |
| realtime_value 实时值表 | 2 | 每测点恒一行，由实时入库脚本按 0.1s 不停刷新（value/ts/alarm/updated_at），模拟完整版"实时接入→库"链路 |

阈值即告警判据存库：`value > alarm_threshold` 即告警，与前端"超限变红"、监视器标红三方同源，保证全链路口径一致。

### 5.4 扩展数据集（四工况 × 20 测点，`data/扩展数据集v2/`）

`生成扩展数据集.py` 产出四个 JSON（每工况 100 行 × 0.1s × time+20 字段），物理曲线按转辙设备机理设计、固定随机种子可复现：

| 工况 | 设计要点 | 库内时间轴 |
|---|---|---|
| 正常转换 | S 形位移 6s 到位 160mm，锁闭/密贴表示正常给出 | 00:00 起 |
| 卡阻 | 3.5s 卡在 88mm，电流爬升至 ~9.5A 保护切除 | 01:00 起 |
| 密贴不良 | 转换完成但终点仅 152mm，密贴表示抖动 | 02:00 起 |
| 锁闭失败 | 位移密贴均到位，锁闭表示缺失，电流三次重试 | 03:00 起 |

`04_扩展数据入库.py` 把 4×2000 条灌入时序表（source=仿真-工况名），是 /trend 历史回放与服务层行为模型回放的数据源。

### 5.5 服务层 API（完整版线核心，v2.1 已跑通）

`数据服务API.py`（FastAPI，端口 8000）把"监测—评估—告警—工单—维修闭环—诊断"整条服务链做成 HTTP 接口，首页即可视化状态板：

- **监测/评估**：/api/realtime 实时值、/api/alarms 告警、/api/health 规则健康度（稳态门+扣分制，优/良/预警/故障）；
- **行为模型回放**：POST /api/play/{工况} 按真实节奏 0.1s 注入实时值表（演示"注入故障→系统反应"）；
- **工单闭环**：告警自动开单（同测点同问题去重）→ /api/repair/{工单号} 维修闭环 → 自动重演正常转换复测 → 健康度回升；
- **工况自动识别（v2.1 新增，答辩难度点）**：/api/identify 把回放窗口压成 8 维统计特征（终点位移/电流峰值/锁闭末态/密贴抖动等），与四工况**同相位前缀**参考特征做加权最近邻匹配，边回放边识别，输出识别工况+置信度+特征依据。可解释统计识别，非黑盒；
- **诊断**：/api/diagnosis = 规则扣分项 + 自动识别 → 对应现场检修规程的维修建议；
- **趋势回放**：/trend 页面按时间轴重演历史，红色虚线告警阈值，1×/2×/4× 变速；
- **工程化（v2.1）**：数据库连接池、CORS 全开（C 页面可跨源直调）、数据库掉线返回 503 带排查提示、历史查询 limit 钳制。

演示入口：双击 `服务API演示.bat`。稳定性验收：`python 稳定性压测.py`（3 分钟全接口轮询，报告错误数/延迟分位数/识别准确率）。

### 5.6 数据库升级 v2（05 升级脚本 + 06 体检，2026-09-27 已应用实测）

在 01 建表基础上加了四层（全部幂等，旧库执行 05 即升级）：

| 层 | 内容 | 答辩问点 |
|---|---|---|
| 文档层 | 全表/关键列中文注释（COMMENT ON），pgAdmin 里直接可见 | 数据库即文档 |
| 性能层 | timeseries_data 增加 source、ts 两个查询索引；体检脚本跑 EXPLAIN ANALYZE 出真实执行计划（历史查询 0.1ms 走索引、超阈联查 1ms） | 索引设计依据 + 执行计划分析 |
| 审计层 | **alarm_event 表 + 入库触发器 trg_timeseries_alarm**：数据一进库自动比对阈值，超阈留痕（(测点,时间戳) 唯一约束防重复）；应用层告警之外数据库层再兜一层；/api/alarms 直接返回最近审计记录 | 触发器/事务/审计兜底思想 |
| 分析层 | 4 个视图：v_point_latest 实时联表、v_alarm_records 超阈明细、v_source_stats 数据源统计（四工况一屏对比）、v_data_quality 每测点时序断点（窗口函数 lag） | 视图/窗口函数 |

体检入口：`python db/06_数据库体检.py`（9 项：对象/分布/质量/执行计划/缓存命中率），当前 9/9 通过；自检脚本 v2 同步含数据库 v2 检查（16 项全绿）。

## 6. 用法速查（按"你要干什么"查）

### 6.1 联调前自检（每周联调第一步）
```bash
python data/联调自检脚本.py
```
10 秒查完三大项：① data.json 契约（80 条/0.1s/三字段/超限演示段）② WebSocket 推送就绪 ③ 数据库连通 + 五张表行数 + 超阈值记录。**全部 [OK] 即 B 侧健康**，联调出问题先查 C 的页面或 A 的数据；有 [NG] 按提示修（脚本内含常见故障的处理提示）。

### 6.2 C 要联调数据
- 默认：直接读 `data/data.json`，按第 3 节契约换算、判阈、循环播放。
- 想要实时推送：B 起 `WebSocket推送服务.py`，C 连 `ws://<B的IP>:8765`。

### 6.3 A 交来 UM 仿真数据（第 3-5 周计划）
```bash
python data/仿真数据转换脚本.py --file um_data.csv             # 生成 um_data.json
python data/仿真数据转换脚本.py --file um_data.csv --step 0.01 # UM 步长不是 0.1s 时指定
```
脚本自动校验：列名（脚本顶部 CONFIG 三行可改）、步长均匀、无非数值，坏了报错不产脏数据；转完打印最大值是否超限。**替换 data/data.json 前必须群通知**；入库换源时加 `--reset`（见 6.4）。

### 6.4 数据入库 / 换数据源
```bash
python db/02_数据导入脚本.py                    # 默认导入 data/data.json
python db/02_数据导入脚本.py --file 新数据.json  # 导入指定文件
python db/02_数据导入脚本.py --reset            # 换数据源时必加：先清空时序表
```
关键逻辑：时序表主键是 (测点, 时间戳)，假数据与 UM 数据时间同为 0~7.9s——**重复导同一文件不加 --reset（自动跳过）；换新数据源必须加 --reset**，否则新数据全部因主键冲突被跳过。连接参数支持 PGHOST/PGPORT/PGUSER/PGPASSWORD/PGDATABASE 环境变量覆盖。

### 6.5 演示"库里的实时表格"
双击 **实时表格演示.bat**：自动启动实时写入（新窗口）+ 打开每秒自动刷新的 psql 实时表格；或手动：
```bash
python data/实时数据入库.py        # 写入侧，Ctrl+C 停
```
```sql
SELECT point_code 字段, value 值, to_char(ts,'HH24:MI:SS') 仿真时刻, alarm 告警

```

### 6.6 队友不装数据库看数据 / 换机重建库
