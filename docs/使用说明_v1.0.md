# 道岔数字孪生 · B 线数据管道 使用说明 v1.0（写给组长/新同学）

> 本文档回答三个问题：**装什么、按什么顺序运行、每个文件是干什么用的。**
> 全程不需要记命令——日常使用只需要双击 3 个 bat；本文末尾才给出等价的命令行写法。
> 环境：Windows 10/11。以下所有"双击"都指双击文件运行。

---

## 一、这套东西是什么（30 秒）

三人分工：**A**（建模仿真，提供 CSV/模型）→ **B**（我们：数据管道，校验→入库→推送→接口）→ **C**（iTwin 页面，变红/恢复展示）。

B 线交付的核心是三个"服务"：

| 服务 | 地址 | 作用 |
|---|---|---|
| 数据服务 API | http://localhost:8000 | 健康度/告警/工单/历史查询/回放，自带网页 |
| WebSocket 推送 | ws://B机IP:3003 | 给 C 的 iTwin 页面实时推数据（0.1s 一帧） |
| PostgreSQL 数据库 | localhost:5432 | 存所有时序/告警/工单数据（开机自启，不用管） |

注意端口：**3002 是 C 页面自己的服务**，我们的推送用 **3003**，互不冲突。

## 二、从零安装（新电脑 20 分钟；老电脑跳过本节）

### 1. 安装 Python

- 官网下载 Python 3.12+ 安装（本机装在 `D:\PY`，供参考）。
- 验证：开命令行输入 `python --version`，能出版本号即可。
- （我们的 bat 会自动找 python：先找 PATH，再找 D:\PY，所以装哪都行。）

### 2. 安装 PostgreSQL 17

- 官网下载安装，记住两样：**密码设为 postgres**（端口默认 5432），其余全部默认。
- 装完它就是 Windows 服务 `postgresql-x64-17`，**开机自启，以后不用再管**。
- 验证：命令行 `sc query postgresql-x64-17` 显示 RUNNING 即可。

### 3. 安装 Python 依赖（一条命令）

在**项目根目录**开命令行（文件夹地址栏输 cmd 回车）：

```
pip install -r requirements.txt
```

（装 websockets / fastapi / uvicorn / psycopg2-binary 四个包，共约 1 分钟。）

### 4. 把数据库建出来（二选一，推荐方式 A）

**方式 A：整库恢复（1 分钟，推荐）**——把随仓库交付的备份恢复回去：

```
"D:\PostgreSQL\bin\psql.exe" -U postgres -h localhost -c "CREATE DATABASE turnout_twin"
"D:\PostgreSQL\bin\psql.exe" -U postgres -h localhost -d turnout_twin -f "data\导出数据\turnout_twin_整库备份_20261002.sql"
```

（第一行如果报"已存在"忽略即可；两处 `D:\PostgreSQL` 换成你的实际安装目录。密码都是 postgres。）

**方式 B：脚本逐步建库**（了解原理用，顺序执行 db 目录下 SQL/脚本）：
`01_建表与种子数据.sql` → `05_批次与来源升级.sql` → `05_数据库升级v2.sql` → `08_告警事件段恢复时刻修正.sql` →（可选）`04_扩展数据入库.py` →（可选）`07_运维历史入库.py`。

### 5. 一键自检

在项目根目录命令行运行 `python data/联调自检脚本.py`——
逐项检查数据文件、依赖库、端口、数据库表行数，全 [OK] 即环境就绪。

> 换机部署的完整图文版见 `docs\换机部署指南_v1.0.md`。

## 三、日常使用：按这个顺序双击（3 个文件）

> 顺序原则：**先数据库（自动）→ 再 API（8000）→ 最后推送（3003）**。
> 数据库是服务不用管，所以日常只需双击下面 1~2 个。

### 第 1 步：双击 `data\服务API演示.bat`

- 黑窗口出现 `Uvicorn running on http://127.0.0.1:8000` = 成功；
- 浏览器自动打开**首页** http://localhost:8000 ——健康度、工单看板、告警变化记录；
- 在首页点工况名（如"卡阻"）即可注入数据回放，观察健康度跌落/工单生成；
- **这个窗口要一直开着**（关掉=服务停）。

### 第 2 步（需要给 C 页面推数据时）：双击 `data\WebSocket演示.bat`

- 黑窗口出现 `[服务] 已启动 端口3003` = 成功；
- C 的 iTwin 页面连接 `ws://你的IP:3003`（跨机用 B 机 IPv4）即可收数变红；
- 不联调 C 时可以不开这个。

### 第 3 步：看网页（浏览器地址栏输入）

| 网页 | 地址 | 看什么 |
|---|---|---|
| 状态板首页 | http://localhost:8000/ | 健康度评分、工单闭环、**告警变化记录**（何时超限→何时恢复） |
| 历史趋势 | http://localhost:8000/trend | 任一测点曲线回放（可 0.25× 慢放、暂停） |
| **五路位移总览** | http://localhost:8000/trend5 | 尖轨3路+心轨2路同图，阈值虚线+模型节点图例（讲解用） |
| WebSocket 自检页 | 双击 data\WebSocket测试页面.html | 不开服务也能看页面；开了 3003 可看实时数值/曲线/告警 |

### 收工

直接关掉两个黑窗口即可（或窗口里 Ctrl+C）。数据库数据保留，下次双击继续。

## 五、一条数据的完整旅程（讲原理时用）

```
A 的仿真 CSV
   │  python data/仿真数据转换脚本.py --file 输入.csv > 输出.json
   ▼
契约 JSON（校验：缺字段/字符串/NaN/Infinity/乱序 → 拒绝并定位行号）
   │  python db/02_数据导入脚本.py --file 输出.json --source um --batch UM-1001
   ▼
PostgreSQL（timeseries_data 带批次；超阈值自动触发器写 alarm_event）
   │                              │
   ▼                              ▼
数据服务 API(8000)            WebSocket 推送(3003)
/trend /trend5 /api/history    0.1s 一帧（time=UTC ISO 当前时间）
/api/alarm-events …            C 的 iTwin 页面变红/恢复
```

## 六、常见问题排错（按现象查）

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击 bat 闪退/提示找不到 python | 未装或不在 PATH | 装 Python 或确认装在 D:\PY |
| 8000 起不来，报 10048 端口占用 | 上次的旧窗口没关 | 命令行 `netstat -ano|findstr :8000` 找 PID，任务管理器结束旧 python |
| API 页面报数据库连接失败 | PostgreSQL 服务没跑 | 管理员命令行 `net start postgresql-x64-17` |
| C 页面连不上 3003 | 推送服务没开/跨机没关防火墙 | 双击 WebSocket演示.bat；防火墙放行 3003 |
| 首页显示"无数据" | 正常设计（不虚报健康度） | 首页点任意工况开始回放 |
| 告警恢复时间看着不对 | 旧库未执行 08 迁移 | 执行 db\08_告警事件段恢复时刻修正.sql |
| 想确认环境是否完整 | — | 跑 `python data/联调自检脚本.py`，再跑四个验收测试 |
