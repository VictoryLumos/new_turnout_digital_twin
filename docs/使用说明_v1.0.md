# 道岔数字孪生 · B 线数据管道 使用说明 v1.1（在组长/任何一台新电脑上跑通）

> 本文档回答三个问题：**装什么、按什么顺序运行、每个文件是干什么用的。**
> 按"一台什么都没装的新电脑"来写——从零到看到页面约 **20~30 分钟**。
> 全程只需要双击和照抄命令，不需要懂 Python / 数据库。
> 环境：Windows 10/11。

---

## 一、这套东西是什么（30 秒）

三人分工：**A**（建模仿真，提供 CSV/模型）→ **B**（我们：数据管道，校验→入库→推送→接口）→ **C**（iTwin 页面，变红/恢复展示）。

B 线交付的核心是三个"服务"，**全部跑在你自己的电脑上**：

| 服务 | 地址 | 作用 |
|---|---|---|
| 数据服务 API | http://localhost:8000 | 健康度/告警/工单/历史查询/回放，自带网页 |
| WebSocket 推送 | ws://本机IP:3003 | 给 C 的 iTwin 页面实时推数据（0.1s 一帧） |
| PostgreSQL 数据库 | localhost:5432 | 存所有时序/告警/工单数据（装好后开机自启，不用再管） |

注意端口：**3002 是 C 页面自己的服务**，我们的推送用 **3003**，互不冲突。

## 二、安装（新电脑一次性的，共 3 步）

### 第 1 步：安装 Python

1. 官网 python.org 下载 Python 3.12 或更新版本；
2. 安装第一屏**务必勾选 "Add python.exe to PATH"**，然后一路默认下一步（默认装在 C 盘即可）；
3. 验证：开始菜单搜 cmd 打开命令行，输入 `python --version`，能显示版本号即可。
   （项目里的启动脚本会自动找 Python：先找系统 PATH，找不到再找 D:\PY——所以装在哪都行。）

### 第 2 步：安装 PostgreSQL 17

1. 官网 postgresql.org 下载 PostgreSQL 17，运行安装器；
2. 安装过程中会让你给超级用户 **postgres 设密码——建议就直接设 `postgres`**（项目默认，省得再改配置）；端口保持默认 5432；其余全部默认下一步；
3. 装完它就是 Windows 服务（开机自启），以后不用管；
4. 验证：命令行输入 `sc query postgresql-x64-17`，显示 `RUNNING` 即可。
   （如果当时设了别的密码：用记事本打开 `data\管道配置.json`，把"password"改成你的密码——全项目只此一处配置。）

### 第 3 步：装 Python 依赖（一条命令）

1. 把整个项目文件夹放到你想放的位置（建议路径里别带太深的中文）；
2. 打开该项目文件夹，在上方**地址栏输入 `cmd` 回车**——就会在项目根目录打开命令行；
3. 粘贴运行：

```
pip install -r requirements.txt
```

（装 websockets / fastapi / uvicorn / psycopg2-binary 四个包，约 1~3 分钟。）

## 三、把数据库建出来（一次性，推荐图形方式 A）

仓库里带了**整库备份**（`data\导出数据\turnout_twin_整库备份_20261002.sql`，含全部表、视图、36400 条数据），恢复它就有完整数据库。

### 方式 A：pgAdmin 图形操作（推荐，全程点击）

1. 开始菜单 → **pgAdmin 4**（装 PostgreSQL 时自带；首次打开要设一个管理密码，自己记住即可）；
2. 左侧展开 Servers → PostgreSQL 17，输入密码 postgres 连接；
3. 右键 **Databases → Create → Database…**，名字填 `turnout_twin`，保存；
4. 点选刚建好的 turnout_twin 数据库 → 菜单 **Tools → Query Tool**；
5. Query Tool 里点打开文件图标（📁），选择项目里的
   `data\导出数据\turnout_twin_整库备份_20261002.sql`；
6. 按 **F5**（或执行按钮）等待执行完（几秒到几十秒）——完成。

### 方式 B：命令行（等价，两条命令）

```
"C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -h localhost -c "CREATE DATABASE turnout_twin"
"C:\Program Files\PostgreSQL\17\bin\psql.exe" -U postgres -h localhost -d turnout_twin -f "data\导出数据\turnout_twin_整库备份_20261002.sql"
```

（第一行若报"已存在"忽略；引号必须保留；两处密码输入你安装时设的。）

### 验证环境（一键自检）

项目根目录地址栏输 cmd 打开命令行，运行：

```
python data\联调自检脚本.py
```

逐项检查数据文件、依赖库、端口、数据库表行数——全 `[OK]` 即环境就绪。

> 从零部署的图文长版见 `docs\换机部署指南_v1.0.md`。

## 四、日常使用：按这个顺序双击（3 个文件）

> 顺序原则：**数据库（服务自启，不用管）→ API（8000）→ 推送（3003）**。日常只需双击 1~2 个。

### 第 1 步：双击 `data\服务API演示.bat`

- 黑窗口出现 `Uvicorn running on http://127.0.0.1:8000` = 成功；
- 浏览器自动打开**首页** http://localhost:8000 ——健康度、工单看板、告警变化记录；
- 在首页点工况名（如"卡阻"）即可注入数据回放，观察健康度跌落/工单自动生成；
- **这个窗口要一直开着**（关掉 = 服务停止）。

### 第 2 步（需要给 C 页面推数据时）：双击 `data\WebSocket演示.bat`

- 黑窗口出现 `[服务] 已启动 端口3003` = 成功；
- C 的 iTwin 页面连接 `ws://你的IP:3003` 即可收数、超限变红、恢复还原、断线自动重连；
- 不联调 C 时可以不开这个。

### 第 3 步：看网页（浏览器地址栏输入）

| 网页 | 地址 | 看什么 |
|---|---|---|
| 状态板首页 | http://localhost:8000/ | 健康度评分、工单闭环、**告警变化记录**（何时超限→何时恢复） |
| 历史趋势 | http://localhost:8000/trend | 任一测点曲线回放（可 0.25× 慢放、暂停） |
| **五路位移总览** | http://localhost:8000/trend5 | 尖轨3路+心轨2路同图，阈值虚线+模型节点图例（讲解用） |
| WebSocket 自检页 | 双击 data\WebSocket测试页面.html | 开着 3003 时可看实时数值/曲线/告警 |

### 收工

直接关掉两个黑窗口即可（或窗口里 Ctrl+C）。数据库数据保留，下次双击继续。

## 六、一条数据的完整旅程（讲原理时用）

```
A 的仿真 CSV
   │  python data/仿真数据转换脚本.py --file 输入.csv > 输出.json
   ▼
契约 JSON（校验：缺字段/字符串/NaN/Infinity/乱序 → 拒绝并定位行号）
   │  python db/02_数据导入脚本.py --file 输出.json --source um --batch UM-1001
   ▼
PostgreSQL（timeseries_data 带批次；超阈值自动触发器写 alarm_event）
   │                              │
   ▼                              ▼
数据服务 API(8000)            WebSocket 推送(3003)
/trend /trend5 /api/history    0.1s 一帧（time=UTC ISO 当前时间）
/api/alarm-events …            C 的 iTwin 页面变红/恢复
```

## 七、常见问题排错（按现象查）

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击 bat 闪退/提示找不到 python | 未装 Python 或没勾 Add to PATH | 重装 Python 勾选 Add to PATH；或装到 D:\PY |
| 8000 起不来，报 10048 端口占用 | 上次的旧窗口没关 | 命令行 `netstat -ano|findstr :8000` 找 PID，任务管理器结束旧 python |
| API 页面报数据库连接失败 | PostgreSQL 服务没跑/密码不对 | 命令行 `sc query postgresql-x64-17`；密码不同则改 `data\管道配置.json` |
| C 页面连不上 3003 | 推送服务没开/跨机没关防火墙 | 双击 WebSocket演示.bat；防火墙放行 3003 |
| 首页显示"无数据" | 正常设计（不虚报健康度） | 首页点任意工况开始回放 |
| 告警恢复时间看着不对 | 旧库未执行 08 迁移 | 执行 db\08_告警事件段恢复时刻修正.sql（整库备份恢复的不需要） |
| 想确认环境是否完整 | — | 跑 `python data\联调自检脚本.py`，再跑四个验收测试 |

## 八、验收怎么复现（复验用）

```
python 验收测试.py           # 31 项（非法拒绝/边界/阶段/批次）
python 验收测试_第二轮.py      # 33 项（time格式/历史日期/重复导入/断线）
python 验收测试_第三轮.py      # 23 项（停机重试/全字段/幂等/页面）
python 验收测试_第四轮.py      # 5 项（恢复时刻/体检/停机指引）
右键管理员运行 data\数据库停机恢复实测.bat   # 真实停机记录（自动写入 docs）
```

全部 0 失败 = 与四轮整改验证记录一致。共 92 项实测（31+33+23+5），记录都在 docs\ 下。
