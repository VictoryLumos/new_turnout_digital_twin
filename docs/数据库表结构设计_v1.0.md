## 1. 定位说明

- 《分工》《统一标准》定死的**基础版不建数据库**：数据源是 `data.json` 文件，本设计不影响基础版联调。
- 本设计对应《完整版》第 4 节平台架构中的两项目标：**关系数据库 PostgreSQL + 时序数据库（InfluxDB / TimescaleDB 二选一）**。
- 本文档是数据库搭建的第一步交付物：把《完整版》编码映射表（20 行）转化为可建库的表结构，供 A 确认、三人各存一份。

## 2. 选型结论

**采用 PostgreSQL + TimescaleDB 扩展，单实例同时承担关系库与时序库两个角色。**

理由：
1. TimescaleDB 本身就是 PostgreSQL 的扩展，一份安装满足文档里两个数据库要求；
2. SQL 语法与 PostgreSQL 完全一致，Python 用 psycopg2 一套驱动通吃；
3. 团队无需维护两套系统（若选 InfluxDB 则要另学其查询语言 Flux/InfluxQL）；
4. 未安装 TimescaleDB 时，`schema.sql` 注释掉两行即可退化为普通 PostgreSQL 使用，基础数据不受影响。

数据库名：`turnout_twin`

## 3. 总体结构

```
component（构件表） 1 ──── N measurement_point（测点表） 1 ──── N timeseries_data（时序数据表）
                                │ 1
                                └──── N work_order（工单表，预留）
```

- 构件表 = 映射表按"构件编码"去重后的 9 个构件；
- 测点表 = 映射表 20 行，一行一个测点（传感器挂在测点上）；
- 时序数据表 = 按"时间戳 + 测点编码 + 数值"的长表存储，`data.json`、UM 数据、将来真实传感器数据统一进这张表，`source` 字段区分来源（对应《完整版》第 3 节数据源清单）；
- 工单表 = 预留，仅预置映射表中的工单编号，完整版做"告警与工单联动"时启用。

## 4. 表结构明细

### 4.1 component（构件表）

| 字段 | 类型 | 约束 | 说明 | 示例 |
|---|---|---|---|---|
| component_code | TEXT | 主键 | 构件编码 | T01-SR-01 |
| turnout_id | TEXT | 非空 | 道岔编号 | T01 |
| component_type | TEXT | 非空 | 构件类型：SR/PR/SM/FR/GR/BR | SR |
| model_node | TEXT | — | glTF 几何主节点名（A 导出后确认） | SwitchRail |
| asset_id | TEXT | 唯一 | 资产ID | AS-002 |
| remark | TEXT | — | 备注 | — |

### 4.2 measurement_point（测点表）

| 字段 | 类型 | 约束 | 说明 | 示例 |
|---|---|---|---|---|
| point_code | TEXT | 主键 | 测点编码 | T01-SR-01-DISP |
| component_code | TEXT | 外键→component | 所属构件 | T01-SR-01 |
| point_type | TEXT | 非空 | 测点类型（见 8.2 待确认） | DISP |
| sensor_id | TEXT | 唯一 | 传感器ID | SEN-001 |
| field_name | TEXT | 唯一、非空 | 数据字段名（小驼峰，与 data.json 字段一致） | switchRailDisp1 |
| node_name | TEXT | — | 映射表"模型节点名"列原文 | SwitchRail_1_FORCE |
| unit | TEXT | — | 单位 | mm |
| alarm_threshold | REAL | — | 告警阈值（数值 **大于** 该值触发告警） | 150 |
| remark | TEXT | — | 备注 | — |

### 4.3 timeseries_data（时序数据表，TimescaleDB hypertable）

| 字段 | 类型 | 约束 | 说明 | 示例 |
|---|---|---|---|---|
| ts | TIMESTAMPTZ | 主键成分 | 时间戳；数据契约中的 time（秒）在导入时换算 | 2026-09-26 00:00:00.4+08 |
| point_code | TEXT | 主键成分、外键→measurement_point | 测点编码 | T01-SR-01-DISP |
| value | REAL | 非空 | 数值，单位见测点表 unit | 12.34 |
| source | TEXT | 非空，默认 'fake' | 数据来源：fake / um / sensor / … | fake |

主键 (point_code, ts)：同一测点同一时刻只有一条，重复导入自动跳过；ts 为分区键建 hypertable。

### 4.4 work_order（工单表，预留）

| 字段 | 类型 | 约束 | 说明 | 示例 |
|---|---|---|---|---|
| work_order_id | TEXT | 主键 | 工单ID | WO-2024-001 |
| point_code | TEXT | 外键→measurement_point | 关联测点 | T01-SR-01-DISP |
| status | TEXT | 默认 'reserved' | 预留 | reserved |
| remark | TEXT | — | 备注 | — |

### 4.5 realtime_value（实时值表，2026-09-26 新增）

每个测点恒一行，值由 `data/实时数据入库.py` 按 0.1s 循环刷新（模拟完整版"实时接入→库"链路，基础版用于演示库内实时表格；查看用 `\watch 1` 或 pgAdmin 刷新）。

| 字段 | 类型 | 约束 | 说明 | 示例 |
|---|---|---|---|---|
| point_code | TEXT | 主键、外键→measurement_point | 测点编码 | T01-SR-01-DISP |
| value | REAL | 非空 | 当前值 | 160.0 |
| ts | TIMESTAMPTZ | 非空 | 该值对应的仿真时刻 | 00:00:07.9 |
| alarm | BOOLEAN | 默认 FALSE | 是否超该测点阈值 | true |
| updated_at | TIMESTAMPTZ | 默认 now() | 本行最后刷新时间 | 17:38:53.8 |

## 5. 种子数据

`schema.sql` 内置种子数据，全部来自《完整版》编码映射表：

- 构件 9 条：T01-BR-01 ~ T01-GR-01（含资产 AS-001 ~ AS-009）；
- 测点 20 条：SEN-001 ~ SEN-020，数据字段与 `data.json` / 前端字段一一对应；
- 工单 20 条：WO-2024-001 ~ WO-2024-020（预留状态）。

## 6. 告警阈值落地

阈值存在测点表 `alarm_threshold` 字段，数值大于阈值即告警（与前端"超限变红"同一判据，来源《统一标准》第 5 节）：

| 测点 | 字段 | 阈值 |
|---|---|---|
| T01-SR-01-DISP | switchRailDisp1 | 150 mm |
| T01-PR-01-DISP | pointRailDisp1 | 100 mm |

其余测点阈值为空，待定后由 UPDATE 补充（改库即通知团队）。

## 7. 文件清单与用法

| 文件 | 位置 | 作用 |
|---|---|---|
| 本文档 | docs/数据库表结构设计_v1.0.md | 第一步交付物，供 A 评审 |
| 建库脚本 | db/01_建表与种子数据.sql | 建表 + 种子数据，装完 PostgreSQL 后执行 |
| 导入脚本 | db/02_数据导入脚本.py | 把 data.json 导入时序数据表并验证 |
| 假数据 | data/data.json | 基础版联调数据（80 条 / 0.1s 步长 / 循环播放），同时是数据库第一批入库数据。**文件名由《统一标准》接口契约定死（"data/ 里放 data.json"），C 按此名读取，不得改名** |

建库三步（装好 PostgreSQL + TimescaleDB 之后）：

```
1) psql -U postgres -c "CREATE DATABASE turnout_twin;"
2) psql -U postgres -d turnout_twin -f "db/01_建表与种子数据.sql"   # 中文乱码时先 set PGCLIENTENCODING=UTF8
3) pip install psycopg2-binary && python db/02_数据导入脚本.py
```

## 8. 待确认事项（评审重点）

### 8.1 必须确认
1. **表结构是否认可**：字段增减、命名是否要调整（A 主责编码表，确认后本设计冻结，谁改谁通知）。

### 8.2 评审时发现的文档问题（建议 A 一并处理）
1. 《完整版》编码规则只定义了 5 种测点类型（DISP/FORCE/CURR/VIB/TEMP），但映射表实际还用了 POWER、WEAR、WRF-L、WRF-V、LOCK、CLOSE。本设计按"后缀原样入库"处理（point_type 为自由文本，不受影响），建议 A 补全编码规则。
2. 映射表"模型节点名"逐行不同（如 SwitchRail 与 SwitchRail_1_FORCE 同属 T01-SR-01），本设计拆成两处存：`component.model_node` 存几何主节点，`measurement_point.node_name` 存行内原文。待 A 确认这个拆法。
3. 《分工》说基础版用 Three.js，《统一标准》第 7 节写 C 用 iTwin.js，两份文档矛盾，影响 C 不影响本设计，建议群里统一口径。
