## 四、WebSocket 消息契约 v2（C 对接用）

每 0.1s 一条 JSON（round 循环，从 round=1 递增）：

```json
{
  "time": "2026-10-02T08:00:02.100Z",
  "simTime": 2.1, "timeStr": "16:00:02.100",
  "seq": 23, "round": 1, "sendTs": 1759382400000, "dataSource": "SIMULATED",
  "switchRailDisp1": 150.1, "switchRailDisp2": 145.1, "switchRailDisp3": 140.1,
  "pointRailDisp1": 80.0,  "pointRailDisp2": 75.6,
  "simFields": ["switchRailDisp2", "switchRailDisp3", "pointRailDisp2"]
}
```

- **`time`：UTC ISO 8601 当前时刻字符串**（iTwin 页面要求：Date.parse 可解析、
  必须为发送当下时间——与浏览器时差>10 秒的帧会被拒收、且不得倒退）。
  仿真时间轴请用 `simTime`（秒）；`timeStr` 为本地展示格式（配置可调）；
- 五路位移单位均 mm；推送 扩展数据集v2 工况时含全部 21 字段（无 simFields）；
- `simFields`：**该消息中由适配层模拟生成的通道清单**，依据=A 确认的设计动程
  等比例换算（switchRailDisp2=disp1×118/160、disp3=disp1×75/160、
  pointRailDisp2=disp1×55.5/100.6，源：编码与映射表.json 第2页8.2/8.5）——
  属演示用近似，**不是设计值或实测值**；A 提供真实三路后自动消失；
- 新鲜度判据：`seq` 全局递增；循环归零时 `round+1`，前端不会误判旧数据；
- 断线：客户端自动重连由 **C 实现**（参考代码见 WebSocket测试页面.html 的 onclose→2s 重连）；
- 告警由前端按阈值判定（等于不告警）。

## 六、历史/回放接口（C 调用）

```
GET /api/history/T01-SR-01-DISP?start=2026-09-26T04:00:00+08:00&end=2026-09-26T04:12:00+08:00&source=仿真-告警演示&batch=B02-四工况-告警演示
GET /api/history/T01-SR-01-DISP?start=2026-09-26T04%3A00%3A00%2B08%3A00   # URL编码的 +08:00 也支持
GET /api/history/T01-SM-01-CURR?source=um&format=csv                      # 导出CSV（含日期/时刻ISO列）
GET /trend                                                                # 趋势回放页（含告警演示时段）
```

start/end 支持：ISO 8601（含时区/`Z`，跨时区自动换算）、`YYYY-MM-DD HH:MM[:SS]`、
`YYYY-MM-DD`（当日 00:00 起）；无时区按北京时间。纯 `HH:MM` 已停用（历史数据跨多日有歧义，返回 400 提示完整格式）。

批次命名：`B01-基础联调` / `B02-四工况-*` / `IMP-日期-时分`（02 默认）/ 自定义 `--batch`。UM 数据请 `--source um`，**不会被写成 fake**。
