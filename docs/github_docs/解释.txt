1．《接口契约.md》——程序之间怎样交换数据
这是给开发人员看的对接规则，主要包括：
• 数据字段：尖轨三个测点 switchRailDisp1/2/3，心轨两个测点 pointRailDisp1/2，以及时间 time。
• 单位：五个测点的位移都用毫米，不能把模型使用的“米”直接混进来。
• 设计动程：尖轨为 160、118、75 mm；心轨为 100.6、55.5 mm。
• 演示告警：尖轨第一点大于 150 mm，对应尖轨变红；心轨第一点大于 100 mm，对应心轨变红。其他三个测点没有设置阈值。
• 断线规则：超过5秒没收到有效数据，会提示停止更新，并保留上次数值和颜色。
这里特别区分了：设计动程是设计参数，演示阈值不是经过工程确认的故障限值。

其余字段中：
• 构件编码、资产ID：用于识别构件，目前是项目内部编码。
• 传感器ID：目前为 null，表示尚未配置真实传感器。

3．《模型说明.md》——模型由什么组成、放在哪里
这份文件解释模型的结构和使用边界：
• 节点名称：例如 StockRail 是基本轨，SwitchRail 是尖轨，PointRail 是心轨。Frog 是组织心轨、翼轨的总成节点，不是额外叠加的一块实体。
• 坐标方向：源模型、Blender和本地iModel中，X沿线路、Y横向、Z向上。GLB导出后坐标轴会转换，文档写明了转换关系。
• 几何单位：源数据为毫米，Blender、GLB和本地iModel使用米。
• 初始位置：列出了全部构件的包围盒中心坐标。这个位置用于定位模型，不是传感器安装点，也不是钢轨机械零位。
• 尺寸：列的是构件在X、Y、Z方向的包围盒跨度，不一定等于弯曲钢轨的实际长度。
• 简化说明：心轨、翼轨、护轨仍是简化几何；转辙机为示意外形，未补造电务图纸中缺失的杆件、锁闭机构等细节。
三份文件都明确记录了当前状态：模型可用于本地展示和模拟联调；真实传感器、Bentley云同步及AssetWise尚未接通。
