## 1. 数据文件契约

| 项 | 约定 |
|---|---|
| 文件 | `data/data.json`（文件名定死，不得改名） |
| 格式 | JSON 数组，一行一个时刻 |
| 字段 | `time`（秒）、`switchRailDisp1`（尖轨位移，mm）、`pointRailDisp1`（心轨位移，mm） |
| 时间步长 | 0.1 秒 |
| 条数 | 80 条，覆盖 0.0 ~ 7.9 秒 |
| 播放 | 循环播放（由前端处理） |
| 坐标换算 | 毫米 × 0.001 = 米（C 端移动模型时换算） |

数据样例（首条 / 末条）：

```json
{"time": 0.0, "switchRailDisp1": 0.0,   "pointRailDisp1": 0.0}
{"time": 7.9, "switchRailDisp1": 160.0, "pointRailDisp1": 95.0}
```

## 2. 假数据曲线设计（当前 data.json）

- 尖轨：0 → 160mm，6 秒平滑完成转换，**5.1 秒起超过 150mm**（后 29 条超限），用于演示"超限变红"；
- 心轨：延迟 0.5 秒启动，0 → 95mm，全程低于 100mm，作为不告警的对照组；
- 将来 A 的 UM 数据按同样字段/步长导出 JSON 即可直接替换，字段不变则 C 无需改代码。

## 3. 告警阈值（前端判定）

| 字段 | 阈值 | 动作 |
|---|---|---|
| switchRailDisp1 | > 150 mm | 尖轨变红 |
| pointRailDisp1 | > 100 mm | 心轨变红 |

数据本身不含告警标记，由 C 在前端按上表判断（与数据库测点表中存储的阈值一致）。

## 4. 推送方式

| 方式 | 说明 | 状态 |
|---|---|---|
| 本地 JSON（默认） | C 的页面直接读 `data/data.json`，循环播放 | 契约默认，随时可用 |
| WebSocket（可选） | `ws://localhost:8765`，0.1s 间隔逐条推送，自动循环 | B 已备好并实测通过（`data/WebSocket推送服务.py`） |

WebSocket 用法（B 的电脑上运行，C 连接）：

```
python WebSocket推送服务.py              # 端口 8765
python WebSocket推送服务.py --port 9000  # 换端口
```

C 在其他电脑：`ws://<B的IP>:8765`（B 运行 `ipconfig` 查 IPv4）。
联调失败按《统一标准》退回本地 JSON，不阻塞交付。

## 5. 字段与测点编码映射（基础版两字段）

| 数据字段 | 测点编码 | 单位 | 阈值 |
|---|---|---|---|
| switchRailDisp1 | T01-SR-01-DISP | mm | 150 |
| pointRailDisp1 | T01-PR-01-DISP | mm | 100 |

完整 20 测点映射见《完整版》编码映射表及《数据库表结构设计_v1.0.md》。

## 6. 变更管理

- 本约定与 data.json 由 B 维护；**谁改谁通知**，修改后群内即时通知 A、C 并更新本文档版本号；
- 新增字段流程：先改本文档 → 群通知 → B 更新 data.json 与推送服务 → C 再改页面；
- 所有文件以共享文件夹为唯一数据源，禁止使用个人本地副本联调。
